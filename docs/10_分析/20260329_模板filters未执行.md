# 模板 filters 配置未被解析器执行

> 创建时间：2026-03-29
> 管线：superpower-chain Pipeline A
> 状态：分析完成

## 现象

Wikipedia 采集结果包含大量 UI 噪音（ambox 编辑提示、[编辑] 链接、规范控制数据库等），尽管 `zh_wikipedia.yaml` 模板定义了 30+ 条清理规则。

## 复现条件

- **命令**：`wf --stdout "https://zh.wikipedia.org/wiki/网络爬虫"`
- **频率**：必现
- **影响**：所有使用 `filters` 段的站点模板均受影响

## 根因分析

### 代码追踪

| 文件 | 行号 | 说明 |
|------|------|------|
| `zh_wikipedia.yaml` | L153-193 | 定义了 `filters.remove_patterns`（30条）、`css_classes_to_remove`（6项）、`ids_to_remove`（3项） |
| `template_parser.py` | L447-473 | 只实现了 `post_processing.remove_elements` 的消费——基于 selector+strategy 的逐条移除 |
| `template_parser.py` | 全文 | **没有任何代码读取 `filters` 段** — grep 确认无 `css_classes_to_remove`、`ids_to_remove`、`remove_patterns` 关键词 |

### 证据链

1. 模板定义 `filters.css_classes_to_remove: ["mw-editsection", "navbox", ...]`
2. `template_parser.py` 的 `parse()` 方法中 BeautifulSoup 预处理阶段（L437-528）只读取 `self.current_template['post_processing']['remove_elements']`
3. `filters` 段完全未被消费 → 模板清理规则形同虚设
4. Wikipedia 模板还缺少 `ambox`（维基百科顶部警告框）和 `hatnote`（消歧义提示）的清理规则

### 根因结论

`template_parser.py` 没有实现 `filters` 配置段的处理逻辑。这是功能缺失，不是配置错误。

### 修复方向

1. 在 `template_parser.py` 的 BeautifulSoup 预处理阶段（L447-474 之后），添加 `filters` 段的三种清理
2. 在 markdown 后处理阶段（L548-551 附近），添加 `remove_patterns` 的正则清理
3. 补充 Wikipedia 模板缺失的 ambox/hatnote 规则
