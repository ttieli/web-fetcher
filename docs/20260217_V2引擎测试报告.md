## 四、V2 竞赛引擎详情

### 4.1 竞赛结果（从 extraction_log.jsonl 提取）

| 域名 | 优胜策略 | 优胜分数 | trafilatura | readability | next_data | json_ld |
|------|----------|----------|-------------|-------------|-----------|---------|
| docs.python.org | trafilatura | 0.800 | **0.800** (3353c) | 0.775 (1723c) | 0 | 0 |
| ruanyifeng.com | trafilatura | 0.950 | **0.950** (11750c) | 0.950 (12424c) | 0 | 0 |
| github.com | trafilatura | 1.000 | **1.000** (2468c) | 0.402 (74c) | 0 | 0 |
| blog.cloudflare.com | trafilatura | 0.950 | **0.950** (15968c) | 0.875 (17340c) | 0 | 0 |

**观察**：
- trafilatura 在当前测试集中全胜，这符合预期（V1 选择 trafilatura 作为主引擎是正确的）
- readability 在阮一峰博客上与 trafilatura 持平（0.950），且提取字符更多（12424 vs 11750）
- readability 在 GitHub 页面表现很差（74 chars），说明竞赛机制在某些场景能有效避免使用劣势策略
- __NEXT_DATA__ 和 JSON-LD 在这组 URL 中均无数据（这些站点不使用这些技术）

## 六、已知限制与后续计划

### 当前限制
1. **V2 性能开销**：多策略竞赛增加约 0.1-2s 解析时间（视页面大小）
2. **fetch_ms 未传递**：当前 V2 日志中 `fetch_ms` 为 0，需从 core.py 传入 fetch_metrics
3. **测试覆盖不足**：尚未测试 SPA 页面、__NEXT_DATA__ 页面、JSON-LD 丰富的新闻页

### Wave 2 计划
- S1: SPA 质量降级检测（SuperPower 20）
- 补充更多 URL 测试（目标 50+）
- 优化 readability 宽松模式重试逻辑

### 默认切换条件
- V2 在 50+ URL 上测试 ≥ V1 的比例达 80%
- 当前：6/6 = 100%（样本量不足，需继续积累）

## 八、结论

**V2 引擎 Wave 1 测试通过。** V1 完全不受影响，V2 功能正常，域名记忆和日志系统运作良好。当前测试集中 V2 输出与 V1 高度一致（trafilatura 全胜），竞赛机制的价值将在 SPA 页面和结构化数据丰富的页面中更明显体现。

**建议**：可以部署到本地使用，通过日常 `wf v2` 积累更多域名记忆数据，为后续 Wave 2 和默认切换提供依据。
