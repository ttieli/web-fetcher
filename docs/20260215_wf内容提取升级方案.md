## 一、当前架构分析

### wf 内容提取的三级 Fallback（`templates.py:424-516`）

```
generic_to_markdown(html, url)
│
├─ Step 1: TemplateParser（站点特定模板）
│  ├─ 匹配到站点模板（非 generic）且提取到内容 → 直接返回
│  └─ 匹配到 generic 模板 → 仅取 metadata，内容跳到 Step 2
│
├─ Step 2: trafilatura（通用内容提取）
│  ├─ bare_extraction(as_dict=True) → 提取 text/title/author/date
│  ├─ 内容非空 → 合并 metadata 后返回
│  └─ 内容为空 → 跳到 Step 3
│
└─ Step 3: legacy parser（兜底）
   └─ legacy.py:1307 — detect_page_type → extract_from_modern_selectors
```

### 当前痛点

1. **trafilatura 是唯一通用内容引擎** — 它失败就只剩 legacy 兜底（效果很差）
2. **无竞赛机制** — 提取结果好坏全靠 trafilatura 一把定，无法横向比较
3. **不识别结构化数据** — 页面有 JSON-LD / `__NEXT_DATA__` 时没利用
4. **readability 算法缺失** — 业界最成熟的正文提取算法没接入

```bash
#!/bin/bash
# test_urllib_baseline.sh — wf urllib 内容提取基线测试
# 用法: bash test_urllib_baseline.sh

OUTDIR="tests/baseline_$(date +%Y%m%d_%H%M%S)"
mkdir -p "$OUTDIR"

URLS=(
  "https://vercel.com/blog/introducing-v0"
  "https://nextjs.org/blog/next-15"
  "https://www.bbc.com/news/technology-67988517"
  "https://docs.python.org/3/library/asyncio.html"
  "https://sspai.com/post/85388"
  "https://github.com/microsoft/TypeScript"
  "https://zh.wikipedia.org/wiki/Python"
)

echo "=== wf urllib 基线测试 ==="
echo "输出目录: $OUTDIR"
echo ""

for i in "${!URLS[@]}"; do
  url="${URLS[$i]}"
  idx=$((i+1))
  echo "[$idx/${#URLS[@]}] $url"

  # 抓取并记录结果
  start=$(date +%s)
  wf "$url" --stdout > "$OUTDIR/test_${idx}.md" 2> "$OUTDIR/test_${idx}.log"
  exit_code=$?
  end=$(date +%s)
  duration=$((end - start))

  # 统计
  if [ -f "$OUTDIR/test_${idx}.md" ]; then
    chars=$(wc -c < "$OUTDIR/test_${idx}.md" | tr -d ' ')
    lines=$(wc -l < "$OUTDIR/test_${idx}.md" | tr -d ' ')
    has_title=$(head -1 "$OUTDIR/test_${idx}.md" | grep -c '^# ')
    images=$(grep -c '!\[' "$OUTDIR/test_${idx}.md")
  else
    chars=0; lines=0; has_title=0; images=0
  fi

  echo "  → exit=$exit_code, ${chars}B, ${lines}行, 标题=$has_title, 图片=$images, ${duration}s"
  echo "$idx|$url|$exit_code|$chars|$lines|$has_title|$images|$duration" >> "$OUTDIR/summary.csv"
  echo ""
done

echo "=== 测试完成 ==="
echo "结果: $OUTDIR/summary.csv"
echo "人工检查: 打开 $OUTDIR/test_*.md 查看提取质量"
```

## 三、完整改进规划

### 架构目标：多策略竞赛 + 评分选优

```
generic_to_markdown(html, url)
│
├─ Step 1: TemplateParser（站点特定模板）— 不变
│  └─ 非 generic 模板命中 → 直接返回
│
├─ Step 2: 多策略竞赛（新增）
│  │
│  │  并行运行 4 个提取器，各自独立打分：
│  │
│  ├─ Strategy A: trafilatura（现有，保持主力）
│  │   └─ bare_extraction → text
│  │
│  ├─ Strategy B: readability（新增）
│  │   └─ python-readability → 正文 HTML → html2text → markdown
│  │   └─ 双模式：严格 → 宽松回退
│  │
│  ├─ Strategy C: __NEXT_DATA__ 提取（新增）
│  │   └─ 检测 <script id="__NEXT_DATA__"> → JSON 解析 → 提取 pageProps 内容
│  │
│  ├─ Strategy D: JSON-LD 提取（已有，需增强）
│  │   └─ legacy.py:extract_json_ld_content() → 提升为正式策略
│  │   └─ 提取 articleBody / description → markdown
│  │
│  └─ 评分器: score_extraction(result) → 选最高分
│
└─ Step 3: legacy parser（兜底）— 不变
```

### 评分机制设计

```python
def score_extraction(text: str, html: str) -> float:
    """
    对提取结果打分，综合评估质量。

    评分因子：
    1. 内容长度（30%）— len(text)，归一化到 0-1
    2. 结构丰富度（25%）— 包含标题/列表/表格/代码块的数量
    3. 噪音比率（25%）— 导航词、广告词、菜单词的占比（越低越好）
    4. 段落质量（20%）— 平均段落长度（太短=碎片，太长=未分段）
    """
    score = 0.0

    # 长度分（归一化，500 字为满分基准）
    length_score = min(len(text) / 500, 1.0)
    score += length_score * 0.30

    # 结构分
    structures = 0
    structures += text.count('\n## ') + text.count('\n### ')  # 标题
    structures += text.count('\n- ') + text.count('\n* ')      # 列表
    structures += text.count('```')                             # 代码块
    structures += text.count('|')                                # 表格
    struct_score = min(structures / 10, 1.0)
    score += struct_score * 0.25

    # 噪音分（反向）
    noise_words = ['导航', 'nav', 'menu', 'sidebar', 'footer', 'cookie',
                   '登录', 'sign in', 'subscribe', '关注我们']
    noise_count = sum(text.lower().count(w) for w in noise_words)
    noise_score = max(1.0 - noise_count / 5, 0.0)
    score += noise_score * 0.25

    # 段落质量分
    paragraphs = [p for p in text.split('\n\n') if p.strip()]
    if paragraphs:
        avg_len = sum(len(p) for p in paragraphs) / len(paragraphs)
        # 理想段落长度 50-300 字符
        para_score = 1.0 if 50 <= avg_len <= 300 else max(0, 1 - abs(avg_len - 175) / 300)
        score += para_score * 0.20

    return round(score, 3)
```

### 改进项详细设计

#### P1-1: 多策略竞赛框架

**新增文件**: `src/webfetcher/parsing/extractors.py`

```python
"""
多策略内容提取器 — 竞赛式提取 + 评分选优
"""
from dataclasses import dataclass
from typing import Optional
import logging

logger = logging.getLogger(__name__)

@dataclass
class ExtractionResult:
    """单个策略的提取结果"""
    strategy: str          # 策略名
    content: str           # 提取的 markdown 内容
    title: str = ''
    author: str = ''
    date: str = ''
    score: float = 0.0     # 质量评分
    error: str = ''        # 错误信息

def extract_with_competition(html: str, url: str) -> ExtractionResult:
    """
    运行所有提取策略，评分后返回最佳结果。
    """
    results: list[ExtractionResult] = []

    # Strategy A: trafilatura
    results.append(_extract_trafilatura(html, url))

    # Strategy B: readability
    results.append(_extract_readability(html, url))

    # Strategy C: __NEXT_DATA__
    next_result = _extract_next_data(html, url)
    if next_result.content:
        results.append(next_result)

    # Strategy D: JSON-LD
    jsonld_result = _extract_json_ld(html, url)
    if jsonld_result.content:
        results.append(jsonld_result)

    # 评分
    for r in results:
        if r.content:
            r.score = score_extraction(r.content, html)

    # 选最高分
    valid = [r for r in results if r.content]
    if not valid:
        return ExtractionResult(strategy='none', content='')

    best = max(valid, key=lambda r: r.score)
    logger.info(
        f"竞赛结果: {', '.join(f'{r.strategy}={r.score:.3f}' for r in valid)} "
        f"→ 胜出: {best.strategy}"
    )
    return best
```

```python
def _extract_readability(html: str, url: str) -> ExtractionResult:
    """Mozilla Readability 算法（Python 实现）"""
    try:
        from readability import Document
        import html2text

        # 严格模式
        doc = Document(html, url=url)
        content_html = doc.summary()
        title = doc.short_title()

        h = html2text.HTML2Text()
        h.body_width = 0
        h.ignore_links = False
        h.ignore_images = False
        content = h.handle(content_html)

        # 如果内容太少（<120字符），用宽松模式重试
        if len(content.strip()) < 120:
            doc = Document(html, url=url, positive_keywords=["article", "content", "post"])
            content_html = doc.summary()
            content = h.handle(content_html)

        return ExtractionResult(
            strategy='readability',
            content=content.strip(),
            title=title,
        )
    except Exception as e:
        return ExtractionResult(strategy='readability', content='', error=str(e))
```

#### P1-3: `__NEXT_DATA__` 提取器

```python
def _extract_next_data(html: str, url: str) -> ExtractionResult:
    """提取 Next.js SSR 数据"""
    import re, json

    match = re.search(
        r'<script\s+id="__NEXT_DATA__"\s+type="application/json">(.*?)</script>',
        html, re.DOTALL
    )
    if not match:
        return ExtractionResult(strategy='next_data', content='')

    try:
        data = json.loads(match.group(1))
        props = data.get('props', {}).get('pageProps', {})

        # 常见字段名
        content = ''
        for key in ['content', 'body', 'article', 'post', 'markdown', 'html']:
            if key in props and isinstance(props[key], str) and len(props[key]) > 100:
                content = props[key]
                break

        # 深层搜索
        if not content:
            content = _deep_find_content(props)

        title = props.get('title', '') or props.get('name', '')

        # 如果提取到的是 HTML，转 markdown
        if content and '<' in content and '>' in content:
            import html2text
            h = html2text.HTML2Text()
            h.body_width = 0
            content = h.handle(content)

        return ExtractionResult(
            strategy='next_data',
            content=content.strip(),
            title=title,
            author=props.get('author', {}).get('name', '') if isinstance(props.get('author'), dict) else str(props.get('author', '')),
            date=props.get('date', '') or props.get('publishedAt', ''),
        )
    except Exception as e:
        return ExtractionResult(strategy='next_data', content='', error=str(e))


def _deep_find_content(obj, depth=0, max_depth=5):
    """递归搜索 JSON 中最长的文本字段"""
    if depth > max_depth:
        return ''
    if isinstance(obj, str):
        return obj if len(obj) > 200 else ''
    if isinstance(obj, dict):
        best = ''
        for k, v in obj.items():
            if k in ('content', 'body', 'text', 'article', 'markdown', 'html', 'description'):
                candidate = _deep_find_content(v, depth + 1)
                if len(candidate) > len(best):
                    best = candidate
        return best
    if isinstance(obj, list):
        for item in obj[:10]:  # 限制搜索范围
            candidate = _deep_find_content(item, depth + 1)
            if len(candidate) > 200:
                return candidate
    return ''
```

def _extract_json_ld(html: str, url: str) -> ExtractionResult:
    """增强版 JSON-LD 提取（基于现有 legacy.py:extract_json_ld_content）"""
    from webfetcher.parsing.legacy import extract_json_ld_content

    data = extract_json_ld_content(html)
    if not data:
        return ExtractionResult(strategy='json_ld', content='')

    # 优先用 articleBody
    content = data.get('articleBody', '') or data.get('description', '')
    if not content:
        return ExtractionResult(strategy='json_ld', content='')

    return ExtractionResult(
        strategy='json_ld',
        content=content.strip(),
        title=data.get('headline', '') or data.get('name', ''),
        author=data.get('author', {}).get('name', '') if isinstance(data.get('author'), dict) else '',
        date=data.get('datePublished', ''),
    )

## 四、风险评估

| 风险 | 级别 | 缓解措施 |

## 五、总结

**一句话**：baoyu 的多策略竞赛机制值得借鉴，但需要适配 wf 的 Python 生态和三级 fallback 架构。核心改动是在 `templates.py:generic_to_markdown()` 的 Step 2 中引入竞赛式提取（trafilatura + readability + `__NEXT_DATA__` + JSON-LD），通过评分器自动选最优结果。

**不改代码时的行动项**：先跑 `test_urllib_baseline.sh` 收集基线数据。
