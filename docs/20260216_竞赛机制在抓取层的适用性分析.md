## 一、当前 wf 的两层架构

wf 存在两个独立的"多策略"层级：

### 抓取层（Fetch Layer）— 串行降级
```
fetch_html_with_retry()   core.py:1254
│
├─ routing.yaml 配置路由 → 可能直接跳到 selenium/cdp
│
├─ urllib（4次重试，指数退避）
│   └─ 失败 → 错误分类器判断是否可重试
│
├─ CDP (Chrome DevTools Protocol)
│   └─ 失败 → 继续降级
│
├─ Selenium
│   └─ 失败 → 继续降级
│
└─ Manual Chrome（极端情况）
```

### 解析层（Parse Layer）— 串行降级
```
generic_to_markdown()   templates.py:424
│
├─ TemplateParser（站点模板匹配）
│   └─ generic 模板 → 仅取 metadata
│
├─ trafilatura（通用内容提取）
│   └─ 失败/空内容 → 降级
│
└─ legacy parser（兜底）
```

**关键发现**：两层都是**串行降级**，第一个成功就返回，不横向比较质量。

## 二、竞赛机制在抓取层适用吗？

### 结论：**不适合直接竞赛，但适合"先快后质"混合策略**

#### 为什么不适合直接竞赛？

| 因素 | 解析层竞赛 | 抓取层竞赛 |
|------|-----------|-----------|
| **耗时** | ~50ms（纯内存操作） | 1-15秒（网络 I/O） |
| **资源消耗** | 几乎为零 | 启动 Chrome / 占用端口 |
| **并行可行性** | 完全可以 | urllib 可以，CDP/Selenium 资源重 |
| **结果差异** | 同一 HTML 不同提取器结果差异大 | 不同方式拿到的 HTML 通常相同（静态页） |
| **评判标准** | 内容质量可量化打分 | HTML 完整性难量化 |

**根本原因**：解析层竞赛的代价几乎为零（同一份 HTML 跑 4 个纯内存函数），但抓取层竞赛要并行发出多个网络请求，且大多数网页 urllib 拿到的 HTML 和 CDP 拿到的一样——白白浪费资源。

#### 什么场景下 CDP 会比 urllib 好？

| 场景 | urllib 结果 | CDP 结果 | 差异原因 |
|------|------------|---------|---------|
| SPA / CSR | 空壳 HTML（只有 `<div id="app">` ） | 完整渲染 HTML | JS 渲染 |
| 懒加载 | 部分内容 | 完整内容 | IntersectionObserver |
| 反爬（JS 检测） | 403 / 验证页 | 正常页面 | JS 环境校验 |
| 静态 HTML | 完整 | 完整 | **无差异** |
| API 驱动页面 | 原始 HTML + JSON 数据 | 渲染后 HTML | 可能 urllib 更好（拿到原始 JSON） |

**关键洞察**：约 70-80% 的网页是静态或 SSR 的，urllib 和 CDP 结果一样。只有 SPA/反爬场景 CDP 才有优势。

## 三、推荐策略："先快后质"双层智能选择

不做抓取层竞赛，而是做**抓取质量检测 + 按需升级**：

```
新架构（提议）:

fetch_and_extract(url)
│
├─ Step 1: urllib 抓取 HTML（快，<2s）
│
├─ Step 2: 解析层竞赛（4策略，~50ms）
│   ├─ trafilatura
│   ├─ readability
│   ├─ __NEXT_DATA__
│   └─ JSON-LD
│   → 选最高分结果
│
├─ Step 3: 质量检测（新增）
│   ├─ 最佳结果分数 > 0.5 → ✅ 直接输出
│   └─ 最佳结果分数 ≤ 0.5 → ⚠️ 可能是 SPA/反爬
│       │
│       ├─ 检测特征：
│       │   - HTML 中 <script> 占比 > 60%
│       │   - body 文本 < 200 字符
│       │   - 包含 React/Vue/Angular 根节点
│       │   - HTTP 状态码 403/451
│       │
│       └─ 确认 SPA → CDP 重新抓取 → 重新竞赛
│
└─ Step 4: 输出最终结果
```

### 为什么这个方案更好？

1. **零额外开销（80% 场景）**：大多数网页 urllib 抓取 + 竞赛评分 > 0.5，直接返回
2. **智能升级（20% 场景）**：只对"提取质量差"的页面启动 CDP
3. **避免浪费**：不并行发请求，不启动不必要的 Chrome
4. **与现有降级兼容**：现有 urllib → CDP → Selenium 降级链保留，新增的是"解析质量"作为降级触发条件

### 与现有架构的对比

| 维度 | 当前架构 | 提议架构 |
|------|---------|---------|
| urllib 失败时 | 立即降级到 CDP | 同（不变） |
| urllib 成功但内容差 | **不检测，直接输出** | **竞赛打分 → 低分触发 CDP 重试** |
| CDP 启动频率 | 只在 urllib 网络失败时 | 网络失败 + 内容质量差时 |
| 解析引擎 | trafilatura 单引擎 | 4 引擎竞赛 |

**核心价值**：现有架构只在"抓取失败"时降级，新架构在"抓取成功但提取质量差"时也能智能升级。这覆盖了 SPA 页面 urllib 返回 200 但内容为空壳的场景。

## 四、具体检测指标

### SPA/空壳 HTML 检测（判断是否需要 CDP 重试）

```python
def should_retry_with_cdp(html: str, best_score: float) -> bool:
    """判断 urllib 拿到的 HTML 是否需要 CDP 重新渲染"""

    # 1. 竞赛评分太低
    if best_score > 0.5:
        return False

    # 2. HTML 特征检测
    body_text_len = len(re.sub(r'<[^>]+>', '', html))  # 去标签后的文本长度
    script_len = sum(len(m) for m in re.findall(r'<script[^>]*>.*?</script>', html, re.S))
    total_len = len(html)

    # script 占比 > 50% 且正文 < 500 字符 → 大概率 SPA
    if total_len > 0 and script_len / total_len > 0.5 and body_text_len < 500:
        return True

    # 3. 框架根节点检测
    spa_markers = [
        'id="__next"',        # Next.js
        'id="app"',           # Vue
        'id="root"',          # React
        'id="__nuxt"',        # Nuxt
        'ng-app',             # Angular
        'data-reactroot',     # React
    ]
    has_marker = any(m in html for m in spa_markers)
    if has_marker and body_text_len < 500:
        return True

    return False
```

## 七、实测结果（2026-02-16）

### 测试环境
- wf venv: trafilatura ✓, readability-lxml ✓, html2text ✓, pychrome ✓
- Chrome CDP: 检测到端口 9222，但 new_tab 失败（远程调试模式限制），本次仅测试 urllib 层
- 测试 URL: 5 个（Python 文档、维基百科、少数派、Vercel 博客、Cloudflare 博客）

### 竞赛结果汇总

| URL | wf_current | trafilatura | readability | next_data | json_ld | 优胜者 |
|-----|-----------|-------------|-------------|-----------|---------|--------|
| Python asyncio 文档 | **0.800** | 0.800 | 0.775 | — | — | wf (持平) |
| 维基百科 Python | 0.550 | **0.750** | 0.550 | — | — | trafilatura (+36%) |
| 少数派 sspai | 0.511 | 0.511 | **0.513** | — | — | readability (+0.4%) |
| Vercel blog | urllib 404 | — | — | — | — | 无法测试 |
| Cloudflare blog | **0.950** | 0.950 | 0.875 | — | — | wf (持平) |

### 关键发现

1. **trafilatura 在大多数场景已是最优**：3/4 个成功抓取的 URL 中，wf_current（基于 trafilatura）得分最高或持平
2. **维基百科是唯一显著差异**：trafilatura 直接提取比 wf_current（经过 TemplateParser 包装）高 36%，原因是 TemplateParser 的额外处理反而引入了噪音
3. **readability 没有明显优势**：在所有测试中 readability 均略低于或持平 trafilatura
4. **少数派 sspai 所有策略都失败了**：内容只有 ~100 字符，说明 sspai 是 SPA/API 驱动，urllib 拿不到真实内容 → 正是"质量驱动降级到 CDP"的典型场景
5. **__NEXT_DATA__ 和 JSON-LD 本次全部无内容**：测试 URL 中没有 Next.js 站点（Vercel 404），需补充测试

### 结论对架构建议的影响

- **解析层竞赛价值有限**：当前 trafilatura 已经足够好，竞赛机制的收益主要在特殊场景（Next.js / JSON-LD 丰富的站点）
- **抓取层质量检测价值更大**：sspai 的例子完美证明了"urllib 返回 200 但内容为空壳"的场景，这正是需要自动触发 CDP 的场景
- **建议优先级调整**：Phase 2（质量驱动降级）的价值可能比 Phase 1（解析层竞赛）更高

## 八、域名级策略学习 + 日志追踪系统

> 2026-02-17 追加：基于竞赛结果的"经验积累"机制

### 核心思想

每次解析完成后，记录该域名的最优策略。下次遇到同域名 URL 时，直接优先使用上次表现最好的方案，跳过不必要的尝试。同时通过结构化日志持续追踪每个域名的解析表现，支持分析和策略调优。

### 8.1 架构设计

```
完整流程（含策略学习）:

fetch_and_extract(url)
│
├─ Step 0: 查询策略记忆（新增）
│   └─ domain_memory.json → 该域名历史最优策略
│       ├─ 有记录 → 优先使用记录的 fetcher + extractor
│       └─ 无记录 → 走正常流程
│
├─ Step 1: 抓取 HTML
│   └─ 优先使用记忆中的 fetcher（urllib/cdp/selenium）
│
├─ Step 2: 解析层竞赛
│   └─ 优先使用记忆中的 extractor，但仍跑竞赛验证
│
├─ Step 3: 质量检测 + 策略记忆更新（新增）
│   ├─ 记录本次结果到 domain_memory.json
│   ├─ 记录详细日志到 extraction_log.jsonl
│   └─ 如果本次最优策略与记忆不同 → 更新记忆
│
└─ Step 4: 输出最终结果
```

### 8.4 记忆查询逻辑

```python
class DomainMemory:
    """域名级策略记忆"""

    def __init__(self, memory_path: str = None):
        self.path = Path(memory_path or
            Path.home() / ".config" / "webfetcher" / "domain_memory.json")
        self._data = self._load()

    def _load(self) -> dict:
        if self.path.exists():
            return json.loads(self.path.read_text())
        return {"_version": "1.0", "domains": {}}

    def _save(self):
        self.path.parent.mkdir(parents=True, exist_ok=True)
        self.path.write_text(json.dumps(self._data, ensure_ascii=False, indent=2))

    def get_domain(self, url: str) -> str:
        """提取主域名（去掉 www 前缀）"""
        from urllib.parse import urlparse
        host = urlparse(url).hostname or ''
        if host.startswith('www.'):
            host = host[4:]
        return host

    def lookup(self, url: str) -> dict | None:
        """查询域名记忆，返回推荐策略"""
        domain = self.get_domain(url)
        entry = self._data.get("domains", {}).get(domain)
        if not entry:
            return None

        # 记忆过期检查（超过 30 天的记忆降低权重）
        from datetime import datetime, timedelta
        last = datetime.fromisoformat(entry["last_fetched"])
        age_days = (datetime.now() - last).days

        return {
            "domain": domain,
            "recommended_fetcher": entry["best_fetcher"],
            "recommended_extractor": entry["best_extractor"],
            "expected_score": entry["best_score"],
            "needs_cdp": entry.get("needs_cdp", False),
            "confidence": "high" if entry["total_fetches"] >= 3 and age_days < 30
                         else "medium" if entry["total_fetches"] >= 1
                         else "low",
            "age_days": age_days,
        }

    def update(self, url: str, fetcher: str, extractor: str,
               score: float, all_scores: dict):
        """更新域名记忆"""
        domain = self.get_domain(url)
        now = datetime.now().isoformat(timespec='seconds')

        entry = self._data.setdefault("domains", {}).get(domain, {
            "best_fetcher": fetcher,
            "best_extractor": extractor,
            "best_score": 0,
            "avg_score": 0,
            "total_fetches": 0,
            "needs_cdp": False,
            "history": [],
        })

        # 更新统计
        entry["total_fetches"] += 1
        entry["last_fetched"] = now
        entry["last_url"] = url

        # 更新最佳策略（只在分数更高时更新）
        if score >= entry["best_score"]:
            entry["best_fetcher"] = fetcher
            entry["best_extractor"] = extractor
            entry["best_score"] = score

        # 更新 needs_cdp 标志
        if fetcher == "cdp" and score > entry.get("urllib_score", 0):
            entry["needs_cdp"] = True
        if fetcher == "urllib":
            entry["urllib_score"] = max(score, entry.get("urllib_score", 0))
        if fetcher == "cdp":
            entry["cdp_score"] = max(score, entry.get("cdp_score", 0))

        # 追加历史（保留最近 10 条）
        entry["history"].append({
            "score": score,
            "extractor": extractor,
            "fetcher": fetcher,
            "timestamp": now,
        })
        entry["history"] = entry["history"][-10:]

        # 重算平均分
        scores = [h["score"] for h in entry["history"]]
        entry["avg_score"] = round(sum(scores) / len(scores), 3)

        self._data["domains"][domain] = entry
        self._data["_updated"] = now
        self._save()
```

### 8.5 日志记录器

```python
class ExtractionLogger:
    """结构化日志记录器"""

    def __init__(self, log_path: str = None):
        self.path = Path(log_path or
            Path.home() / ".config" / "webfetcher" / "extraction_log.jsonl")

    def log(self, url: str, domain: str, fetcher: str, fetch_ms: float,
            extractor_results: dict, winner: str, winner_score: float,
            memory_hit: bool = False, quality_low: bool = False,
            cdp_retry: bool = False):
        """追加一条日志"""
        self.path.parent.mkdir(parents=True, exist_ok=True)

        record = {
            "ts": datetime.now().isoformat(timespec='seconds'),
            "url": url,
            "domain": domain,
            "fetcher": fetcher,
            "fetch_ms": round(fetch_ms),
            "extractors": extractor_results,
            "winner": winner,
            "winner_score": winner_score,
            "memory_hit": memory_hit,
        }
        if quality_low:
            record["quality_low"] = True
        if cdp_retry:
            record["cdp_retry"] = True

        with open(self.path, 'a', encoding='utf-8') as f:
            f.write(json.dumps(record, ensure_ascii=False) + '\n')
```

### 8.7 与 routing.yaml 的关系

**domain_memory.json 和 routing.yaml 是互补的，不是替代关系**：

| 维度 | routing.yaml | domain_memory.json |
|------|-------------|-------------------|
| **维护方式** | 人工编辑 | 自动学习 |
| **决策层面** | 抓取方式（fetcher） | 抓取 + 解析（fetcher + extractor） |
| **优先级** | **高** — 人工规则优先 | **低** — 只在无人工规则时使用 |
| **适用场景** | 已知的固定模式（反爬、SPA） | 未知站点的经验积累 |
| **变更频率** | 偶尔手动更新 | 每次抓取自动更新 |

**决策优先级链**：

```
1. routing.yaml 人工规则（最高优先级）
   └─ 命中 → 直接使用规则中的 fetcher
   └─ 未命中 → 继续

2. domain_memory.json 学习记忆
   └─ 有高置信度记录 → 优先使用记忆中的 fetcher + extractor
   └─ 无记录或低置信度 → 继续

3. 默认流程（urllib → 竞赛 → 质量检测 → 可能 CDP）
```

### 8.8 自动路由提升

当 domain_memory 中某个域名满足以下条件时，**建议提升为 routing.yaml 规则**（通过 `wf stats --suggest-rules` 输出）：

```python
def should_promote_to_routing(entry: dict) -> bool:
    """判断是否应该提升为 routing.yaml 规则"""
    return (
        entry["total_fetches"] >= 5 and          # 足够多次观测
        entry["needs_cdp"] and                     # 确实需要 CDP
        entry.get("cdp_score", 0) > 0.7 and       # CDP 效果好
        entry.get("urllib_score", 0) < 0.5 and     # urllib 效果差
        (entry["cdp_score"] - entry.get("urllib_score", 0)) > 0.3  # 差距显著
    )
```

### 8.9 记忆衰减机制

防止过期记忆导致错误决策：

```python
def get_confidence(entry: dict) -> str:
    """计算记忆置信度"""
    age_days = (datetime.now() - datetime.fromisoformat(entry["last_fetched"])).days
    fetches = entry["total_fetches"]

    if age_days > 90:
        return "expired"      # 超过 90 天 → 忽略记忆，重新探索
    elif age_days > 30:
        return "stale"        # 30-90 天 → 降低权重，仍跑竞赛验证
    elif fetches >= 5:
        return "high"         # 多次观测 + 新鲜 → 高置信度
    elif fetches >= 2:
        return "medium"       # 少量观测 → 中等置信度
    else:
        return "low"          # 单次观测 → 低置信度，仅供参考
```

| 置信度 | 行为 |
|--------|------|
| **high** | 直接使用记忆的 fetcher + extractor，跳过竞赛 |
| **medium** | 使用记忆的 fetcher，但仍跑竞赛验证 |
| **low** | 仅参考，走完整流程 |
| **stale** | 降权使用，竞赛结果优先 |
| **expired** | 忽略记忆，按新域名处理，重新积累 |

|------|------|
